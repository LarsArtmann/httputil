The model is mostly strong: every config is an explicit struct with a Validate() entry point, middleware is a clean func(http.Handler) http.Handler alias, and classified errors use a consistent http.* code namespace. The problems below are real but bounded — no anemic god-objects, no stringly-typed state machines.

01Problem Catalog

Critical · Contract

CORS allowlist is bypassable: unmatched origin returns "*"

cors.go:142 — resolveOrigin()
func resolveOrigin(origin string, cfg CORSConfig) string {
    if cfg.AllowAllOrigins { return "*" }
    for _, allowed := range cfg.AllowedOrigins { ... return origin }
    return "*" // ← unmatched origin still gets "*"
}

When AllowAllOrigins is false and a request origin matches no entry in AllowedOrigins, the middleware responds with Access-Control-Allow-Origin: *. For simple requests this lets any origin read the response — the allowlist is decorative. This is documented as intentional in DOMAIN_LANGUAGE.md ("If no match → fall back to *"), but it is a security surprise: a consumer configuring an allowlist reasonably expects non-matching origins to be denied.

Why not auto-fixed: Changing the fallback to "deny" (empty header) is a behavior change to a documented contract and could break consumers who rely on the open fallback. Flagged for a deliberate v1 decision.
High · Dead field

CompressionConfig.QValues is declared, documented, never read

compression.go:83-87 — read nowhere in negotiator

The field doc claims it "lets the server hint at preference for clients that omit a quality value," but buildNegotiator and negotiateEncoding never consult cfg.QValues. A consumer setting it gets silently no effect. This is a lying type — the field's existence implies behavior that does not happen.

Options: (a) wire it into the negotiator as the server-side default q-value, or (b) remove it (breaking). Wiring is preferred — the design intent is sound, only the implementation is missing.
High · Split-brain

CompressionConfig.Level is decoupled from WriterFactories

compression.go:62 — vs WriterFactories map

Level is validated but never passed to the factories in Compression(). The actual compression level comes from whatever level the WriterFactories map was built with (DefaultWriterFactories() hardcodes gzip.DefaultCompression). So a consumer who sets cfg.Level = gzip.BestCompression gets no change unless they also rebuild the factory map. Two places encode the same concept; they can disagree.

Fix direction: Make Level the single source of truth and have DefaultWriterFactories (or Compression()) honor it, or remove Level and document factories as the only level control.
Medium · Correctness risk

ETag uses CRC32 — a checksum, not a collision-resistant hash

etag.go:180 — crc32.ChecksumIEEE

CRC32 has a 32-bit output. Two different response bodies can share an ETag, yielding a false 304 Not Modified and serving stale content. For a general-purpose library this is a real (if rare) correctness bug. The tradeoff (zero-alloc, fast) is reasonable, but the collision risk should be opt-out, not silent.

Fix direction: Add an Algorithm option (CRC32 default for speed, xxhash/SHA for correctness) or document the collision semantics explicitly.

02The Vision

What "right" looks like

The model is already close. The improvements are surgical, not structural:

  • Branded error codes — promote the http.* code strings to a named type ErrCode string so they can't be confused with arbitrary strings at call sites.
  • One level knob — Level becomes the single source; factories derive from it.
  • Honest CORS — unmatched origin returns no allow-origin header (deny), with an explicit DenyUnmatched bool escape hatch preserving the old behavior.
  • Pluggable ETag hash — HashFunc func([]byte) uint64 on the config.
