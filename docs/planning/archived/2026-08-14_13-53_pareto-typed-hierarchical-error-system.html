Pareto Execution Plan

Typed, Hierarchical Error System

A ranked execution plan to move httputil from a mixed stdlib / classified error model to a fully typed, hierarchical, go-error-family-native error system.

1% Tier — 51% of value

Establish the typed-code model and convert CORS

Three small tasks create the pattern that every subsequent task copies: a Code type, a domain extractor, typed HTTP constants, and CORS validation converted to classified errors with a test proving the model.

4% Tier — 64% of value

Convert the three critical validators and add hierarchy helpers

Server, Compression, and KeyedRateLimiter configs become classified. Add DomainOf() and InDomain() so consumers can match errors by domain without string parsing.

20% Tier — 80% of value

Convert all remaining validators, register templates, align tooling

Complete CSRF, MaxBodySize, RequestID, SecurityHeaders, Decompression, Metrics, Nonce, RateLimit, and MiddlewareStack validators. Register user-facing templates, centralize write swallows, update AGENTS.md, and fix erraudit policy.

Rest — 100% of value

Polish and future-proof

Migrate string constants to typed codes, add domain predicates, integration tests, README guidance, benchmarks, and consider v1 concrete return types.

05 Anti-Verschlimmbesserung Checklist

  • Does this change break the build? Run go test -race ./... after every code change.
  • Does this introduce a new unclassified error? Every new error must implement Coded/Classified/Contextual.
  • Does this alter a public API signature? Keep Validate() error in v0.x.
  • Does this remove an exported constant? Preserve string aliases like ErrCodeWriteFailed.
  • Does this contradict AGENTS.md? Update the error classification table.
  • Am I running aligned erraudit flags? Do not use --enforce-samber-oops.
