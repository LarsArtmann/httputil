01Findings

F1 · Two parseQValue implementations, no parity oracle

The in-flight endpoints module carries its own q-value parser (endpoints/qvalue.go:28) next to the root's (language.go:357 calls the root copy). The duplication is deliberate — endpoints must stay stdlib-only so it embeds where the root's dependency set cannot go (endpoints/doc.go:22) — but nothing pins the two parsers to the same lenient-posture semantics. The fuzz-oracle lessons (AGENTS testing conventions) exist per copy; a divergence between the copies is invisible to both fuzz targets.

F1 fix · Cross-module parity corpus

Ship a shared seed corpus consumed by both fuzz targets (a committed testdata of Accept-Encoding/Accept-Language q-strings with expected parses), so a semantic drift between the two copies fails at least one module's tests. Fold the R15 dependency-direction ruling (shared parser module vs deliberate duplication) into the same decision.

F2 · go-etag dependency edge retained for one registration

The ETag passthrough adapter was removed in v1.1.0, yet go-etag stays in go.mod for its error-code registration alone. Every consumer pulls the module for a code-path most never execute.

F2 verdict path

Owner-gated: either accept the edge as the documented cost of family-consistent error codes (current state, one sentence in AGENTS), or register the codes locally and drop the dep at the next major. Not urgent — recorded so it is a decision, not an accident.

F3 · The new-code doc sweep is now six files wide

Adding one error code touches: the code+sentinel, errors.go templates, errors_templates_test.go, the domain test, FEATURES.md, docs/v1-stability.md, and the architecture-reference tables. The friction the 2026-09-10 review noted has grown with the doc surface.

F3 fix · Generate the tables from the source of truth

The classification tables in architecture-reference are derivable from errors.go's template map; a small generator (the scripts/ dir already hosts doc tooling) turns the widest part of the sweep into a build step. Trigger: the next code addition that makes the sweep feel heavy — not before.
