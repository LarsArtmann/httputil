00Summary

The architecture is composability-first by design: every middleware shares one signature (func(http.Handler) http.Handler, aliased as Middleware), third-party behavior hides behind five plugin seams, and Chain + MiddlewareStack assemble handlers in declaration order. The one structural gap was that composition always required a handler upfront: there was no way to build a reusable bundle of middleware and apply it later, pass it as a single argument, or nest stacks inside stacks.

That gap is closed in this session. Compose, MiddlewareStack.Middleware(), and MiddlewareFunc.Then landed in compose.go / stack.go with nine new tests; the full race-enabled suite, the 70-linter gate (restored from 13 findings to 0), and both erraudit gates pass.

The bottom line Good architecture (3.9/5) with a deliberate, documented flat-root decision that should NOT be re-opened. The composability ceiling was the missing middleware-to-middleware composition — now shipped. The only remaining open item of substance is nonce generator injection, already tracked in TODO_LIST.md.

◆What's already excellent

+
Uniform middleware signature everywhere All 14 middlewares are Middleware (recorder.go:18), so any piece recombines with any other without adapters. ETag composes directly via the alias (docs/adr/0001).
+
Five plugin seams isolate every external behavior RateLimiter and KeyExtractor (ratelimit*.go), MetricsRecorder (metrics.go:17), CSPBuilder func(string) string and GenerateID func() string function fields (nonce.go:62, requestid.go:15), WriterFactory (compression.go). Redis limiters, Prometheus recorders, brotli writers all fit without core changes.
+

+
Composition is verified, not assumed chain_test.go, stack_integration_test.go, and the httpspec runner pin cross-middleware contracts; fuzz tests pin writer invariants. New composition code ships with 9 tests run 10x under -race.

01Findings

P1 · Fixed this session

No middleware-to-middleware composition

recorder.go:148 (Chain) · stack.go:100 (Build)

Chain(handler, mws...) bakes the handler in immediately. A reusable "secure stack" bundle could not be built once and applied to many handlers, passed as one Middleware argument, or nested — every bundle had to re-thread the handler through at the call site.

Fixed Compose(mws ...Middleware) Middleware (compose.go), (*MiddlewareStack).Middleware() (stack.go), and MiddlewareFunc.Then(handler) for value-level chaining. Ordering mirrors Chain: first = outermost.

02Before / After: the composition API

Before
After (shipped)
// Bundle = inline, handler threaded
// through at every call site:
h := Chain(handler,
    Recovery(),
    Logging(log),
    RequestID(cfg))

// Stack → handler only, never
// reusable as a single unit:
h = stack.Build(handler)
// Bundle once, apply anywhere:
var secure = Compose(
    Recovery(), Logging(log),
    RequestID(cfg))

h := secure(handler)   // as unit
h2 := secure(other)    // reuse

// Nest stacks inside stacks:
outer.Add("inner",
    stack.Middleware())

// Value-level chaining:
var auth MiddlewareFunc = func(next http.Handler) http.Handler {...}
h3 := auth.Then(handler)
Why this matters Middleware bundles become first-class values: build once, pass as arguments, nest, test in isolation. This is the difference between "middleware can be chained" (score 4) and "middleware composes into new middleware" (score 5) on the rubric.
