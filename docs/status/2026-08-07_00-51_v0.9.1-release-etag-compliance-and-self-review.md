### Process

1. **Treat missing release-gate tools as blockers, not skips.** govulncheck missing → install it or escalate. Never silently skip a documented gate.
2. **Annotate prior status reports on read.** I read the gap analysis report, acted on its items, but didn't mark them resolved inline. The report now contains stale claims ("NOT UPDATED") that are false.

4. **Save benchmark data to a persistent artifact.** The Q3 allocation data (60ns/16B for single-tag, 96ns/64B for multi-tag) exists only in this conversation and in the CHANGELOG prose. It should be in a benchmark log or the status report so future sessions can compare without re-running.

### Code

5. **`parseETagList` doesn't handle escaped quotes** — backslash-escaped `\"` flips `inQuotes` incorrectly. RFC 7232 §2.3 permits `%x5C` in quoted-strings. Extremely rare (hex ETags never contain backslashes) but not fully spec-compliant. Now in TODO_LIST.md.
6. **`stripWeakPrefix` doesn't validate entity-tag shape** — blindly removes `W/` from anything starting with those bytes. `W/foo` (unquoted) produces `foo`. Low priority since the comparison can't match valid server ETags against garbage.
7. **ETag middleware overwrites handler-set ETags** — no `SkipIfPresent` config. Design limitation, now documented in AGENTS.md and ROADMAP.md. Scope decision for v1.0.

### Architecture

8. **Conditional-request scope is unresolved.** The ETag middleware handles only `If-None-Match` (GET/HEAD → 304). `If-Match`, `If-Modified-Since`, `Last-Modified`, `If-Range` are all missing. This defines whether httputil is a "caching" library or a "full conditional-request" library. Captured in ROADMAP.md as a v1.0 decision.

## g) Questions I Cannot Answer Myself

### Q1: ~~Should the ETag middleware support `If-Match` / `If-Unmodified-Since` (412 Precondition Failed for unsafe methods)?~~

**Answered:** conditional-request scope is evaluated in go-etag (ROADMAP); not an httputil concern after the extraction.

The middleware is GET/HEAD-only. `If-Match` prevents lost updates on PUT/DELETE/PATCH. Adding it means either widening the method filter or creating a separate precondition middleware. This defines whether httputil is a caching library or a full conditional-request library. It affects v1.0 API surface and scope. **This is a product direction decision I cannot make.**

### Q2: ~~Should we add `SkipIfPresent bool` to `ETagConfig` to preserve handler-set ETags?~~

**Answered:** SkipIfPresent is a go-etag config decision now; ROADMAP tracks the scope.

The middleware currently always overwrites handler-set ETags. Handlers with domain-specific modification semantics (e.g., "this response is a composite of two cacheable fragments") cannot win. Adding `SkipIfPresent` is additive (non-breaking). Changing the default to skip-if-present is a breaking behavior change. **This is a compatibility policy decision that affects v1.0 stability.**
