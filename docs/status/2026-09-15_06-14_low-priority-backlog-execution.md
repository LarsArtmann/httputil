## e) WHAT WE SHOULD IMPROVE

1. **Enumerate gates from the canonical checklist, never from memory.** "All gates green" must mean every gate in `scripts/prerelease-check.sh`, or an explicitly named subset ("build/vet/race/lint green" is honest; a bare "all gates" is not). Impact: prevents the d1 class entirely.
2. **Ban filtered exit codes in session commands.** Any command piped through a filter followed by an exit-status echo reports the filter's status. House style for verification commands: run the command with an `&& echo OK` suffix, or capture the code unfiltered. Impact: kills the pipeline-masking class AGENTS.md documents and this session nearly repeated.
3. **Rule on MD060 once.** The evidence is now complete: the formatter does not align tables (0 changes on a fully misaligned file), the "aligned" style is unmaintainable by hand, and cells containing literal pipes break mechanical fixes. Either bless the single-space compact style (what the LNA doc uses after today's fix; record it in AGENTS.md) or add MD060 to the judged-disable list like the 20 rules disabled on 2026-09-11. Then purge the buildflow result-cache rows so the finding does not replay for 7 days.
4. **Author tables in the style the linter enforces; never hand-pad.** Table style is mechanical; the formatter or a tiny authoring snippet should own it. The "aligned" style is unmaintainable by hand and unverifiable by the current formatter.
5. **ANNOTATE on read is non-negotiable.** When resolving a question by reading old reports, the inline markers land in the same change that resolves the question. Deferral creates the next session's stale-claim risk — this is the second report in a row touching question-② hygiene.
6. **Mutate-run-revert in the same change.** A strengthened or rewritten test should prove it can fail before the session ends; the command is one line, and "verified by reading the source" is the weaker claim the testing conventions explicitly demote.
7. **erraudit's two enforcing gates belong in the habitual post-change batch.** They live outside golangci-lint, so "lint is green" silently excludes them. Habit or a gates wrapper fixes it.
8. **Post-file verification loop.** After creating an issue with a body file, a 30-second `gh issue view` closes the rendering loop — same discipline as post-push CI checks.
9. **Recurring-review scope should become a pre-release checklist row.** The scripts/examples sweep found three real findings despite a prior "clean" claim — that scope deserves a standing line rather than depending on lost review passes being re-noticed.
