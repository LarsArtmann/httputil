### What v0.5.0 Contains (18 commits since v0.4.0)

**New Public API:**

- `ReadyHandlerWithProbe(ready func() bool) http.HandlerFunc` — dependency-based readiness
- `TokenBucketLimiter.EvictionTTL time.Duration` — opt-in lazy bucket eviction
- `ETagConfig.HashFunc func([]byte) uint64` — pluggable ETag hash (default FNV-64a)
- `DefaultWriterFactoriesForLevel(level int) map[string]WriterFactory` — per-level factories
- `CORSConfig.DenyUnmatched bool` — prevent allowlist bypass

**Breaking Changes (acceptable at pre-1.0):**

- `NewTokenBucketLimiter` signature changed: returns `(*TokenBucketLimiter, error)` — validates rate/burst > 0
- `CompressionConfig.QValues` removed — was a lying field (documented, never read)

**Fixes:**

- CORS allowlist bypass: unmatched origins now withhold `Access-Control-Allow-Origin` when `DenyUnmatched: true`
- ETag collision risk: CRC32 (32-bit) → FNV-64a (64-bit, birthday bound ~4 billion)

**Internal:**

- `hex.go` shared lookup table (deduplication)
- `beginPlainResponse()` extraction (deduplication)
- `writeDefaultOK()` extraction (deduplication)
- gosec G705 excluded globally (structural false positive for response-writing library)
- go-error-family v0.5.1 → v0.6.1

## e) WHAT WE SHOULD IMPROVE

### Process Improvements

1. **Release discipline** — 18 commits accumulated with an empty `[Unreleased]` section. The changelog should be updated incrementally per PR/commit, not batched at release time. Consider a `CHANGELOG.md` lint hook.

2. **README API table was stale** — 10 exported functions from v0.4.0 (MaxBodySize, RateLimit, Metrics, NewMiddlewareStack, DetectCapabilities, etc.) were never added to the README API table. This means v0.4.0 shipped with an incomplete README. The release workflow should verify README completeness.

3. **`TODO_LIST.md` zombie state** — Intended for removal, resurrected. Either commit to it or remove it for real. The mixed signals are confusing for any AI session.

4. **Config field tables incomplete** — Only 3 of 8 config types have field detail tables in the README (CORSConfig, ResponseRecorder, CompressionConfig). The rest are discoverable only via godoc. Not broken, but inconsistent.

### Technical Improvements

5. **`NewTokenBucketLimiter` breaking change** — Now returns error, but there's no `MustNewTokenBucketLimiter` convenience variant. Users who know their inputs are valid must write `limiter, err := NewTokenBucketLimiter(rate, burst)` + `if err != nil { panic(err) }`. Consider a panic-on-error variant or document the pattern.

6. **`DenyUnmatched` defaults to `false` (backward-compatible but insecure)** — The default behavior still allows the CORS allowlist bypass. New users opting into `AllowedOrigins` without `DenyUnmatched: true` get a false sense of security. Consider documenting this prominently or flipping the default in v1.0.

7. **No `CHANGELOG.md` version comparison links** — Keep a Changelog format recommends bottom-of-file link references like `[^0.5.0]: https://github.com/.../compare/v0.4.0...v0.5.0`. Missing, but low priority.
