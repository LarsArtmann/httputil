## e) WHAT WE SHOULD IMPROVE (process lessons from this session)

1. **Byte-dump first when an exact-match edit fails twice.** `od -c` / python `repr()` on the second failure; every failed edit after that is guesswork with extra steps. (The capital-letter phantom cost 3 rounds.)
2. **Per-cell strikes, always — never hand-rolled whole-row strikethrough.** The skill's annotate-rows exists precisely because pipes inside `~~` corrupt tables. One custom script = 4 lint findings + 2 fix rounds. If a custom path is unavoidable, run the markdown gate on that file immediately, not at session end.
3. **Marker after evidence, never before.** Write "LSP restarted"/"gates run" markers only once the action's output is in hand; assertion-first markers are untruthful for the window between.
4. **Inferred evidence must say so.** "Observed green" requires an observation; otherwise write "expected green — no contrary signal; verify via gh run list" or route a TODO. My three weakest markers would have been honest with one different verb.
5. **Derive edit anchors from the file, never from memory of the file** — the same lesson the 09-15 sessions recorded (d2/d3 there); my link-block failure was this class in byte form.
6. **Complete the strike when striking multi-clause sentences** — unclosed `~~` renders the whole following paragraph as struck. A one-second read-back of the changed line catches it (mine did; make it every time).
7. **Triage coverage should be labeled in the report, not just known internally** — this report does in b1 what the 04-30 pass did: disclose scale-vs-depth honestly. Keep doing that; the corpus's ~2,300 archived banner-covered items remain the standing debt (owner question, 10-28 f21).
