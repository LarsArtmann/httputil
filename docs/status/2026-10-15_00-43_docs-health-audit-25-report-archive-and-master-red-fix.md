## e) WHAT WE SHOULD IMPROVE

1. **Mechanical spec generation, always.** `emit-keys <file> <lineno…>` produces paste-ready keys; hand-typing spec lists from a read is how d1 happened. Rule of record going forward: print the bare items with line numbers, generate keys from that output, never retype ids. The skill's fixture tests (`annotate-status-items_test.sh`, `annotate.go self-test`) exist for the same reason.
2. **Dry-run one full section before any bulk write on a new file shape.** The skill mandates dry-running the first spec; this session proves the right unit is the whole section (the shift bug would have shown up as visibly wrong pairings in a full-section dry-run diff).
3. **Guards should test for markers, not substrings.** `~~`-presence is the annotation signal; `→` is content-legitimate. A "looks annotated" heuristic must be `~~`-outside-code-spans (what check-rows already does), and "routed" detection should match the exact routed grammar (`→ routed —` / `**→ …**`), never a bare arrow.
4. **Guard the daemon, not just document it.** The `--no-verify` bypass is how both this week's red classes reached master uncaught. A cheap pre-sweep `go build ./... && go vet ./...` (seconds) inside the daemon loop — or a fleet wrapper that refuses Go-file commits when vet fails — converts the typecheck class from "documented hazard" to "mechanically impossible". Same pattern that fixed the art-dupl baseline (pin the mechanism, stop re-promising in prose).
5. **Section-scoped annotation state belongs in the pass record.** Four of this session's five stumbles were shape-discoveries (single-dash separators read as data rows; letter-prefixed ids `c1` vs digit ids; prose-vs-table sections; prior strikes inside an e-section creating in-file precedent). Each was resolved ad hoc; a two-line "file shapes seen" note in the pass record (this report) is what makes the NEXT pass skip the archaeology.
6. **"View ALL files" needs a classification artifact.** When the instruction is view-everything, write down the disposition of every file at inventory time (read / skimmed / classified-not-read + why). This report's b1 exists because that artifact was implicit. The archive README manifest pattern is the right home for it.
